# 透明素材生成和身份门禁

目标是保留用户选定角色，而不是根据描述重新画一个近似角色。已确认的母图只读；每次生成写入独立 candidates/<批次>/，记录输入文件、输出文件、提示词和是否由用户确认。

## 选择路径

1. **当前姿态的小幅动效**：优先原图像素语义拆分 + 共享网格。运行内置 build，不再次生成整个人物。
2. **存在透明部件但排错位置**：先核对同一画布、bbox 与枢轴，不用换画风掩盖坐标错误。
3. **需要露出原本遮挡的区域**：调用当前环境实际可用的 imagegen 编辑能力，用锁定原图作图像输入，遮罩只覆盖需补全区域。先完整读取对应 imagegen Skill；透明背景、图像编辑、尺寸等参数依据实际工具能力填写。没有工具时如实说明，不伪造生成结果。
4. **需要透明部件切出**：使用已安装 image-splitter 的 RGBA 导出能力，或本构建器的已标注原图分区。AI 去底只解决背景，不等于自动骨骼语义拆层。

## 生成任务模板

“保持输入图中的同一个人物：发色/眼色/服装/脸型/轮廓笔触/平面色块/光线不变。只补全 [指定部件] 被遮挡的 [指定区域]，输出透明 RGBA。保持原画布大小与已可见部分位置；关节处补足 [肩/肘/腕] 转动所需的重叠。除遮罩区域外保留原像素。不绘制控制器、骨架、标签、水印，不输出整张新角色。”

按躯干、头发、五官、双臂的依赖顺序逐批生成，不同时让模型自由重画所有部件。每批检查可见像素偏移、身份、透明通道、边缘和预期补底。不同部件若是分别生成，必须先回到统一画布对齐，不能通过各自中心自动缩放拼接。

## 接入门禁

当前 builder 的原像素分区确保 restPixelExact。生成式补绘不能直接覆盖 source.png 或伪造此检查；先建立另一种带 overlap、z-order、pivot 的层导入格式，保留 original/source-pixel/generated 三种来源标签，并增加零姿态对齐和极限动作验收，再接入运行时。

See-through 或其他仓库只能作为可核查的参考，不等于本工具已运行该模型。未执行的模型、隐藏素材重建、生成式自动分层均不能出现在“已完成”描述中。
